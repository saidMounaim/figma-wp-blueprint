How it works

One Figma section becomes one layout, with the same name everywhere

Every section in the design is built the same way: an ACF field group, a page-builder layout, a PHP template part, scoped CSS, and JavaScript only when the section actually moves. Editors add sections in wp-admin; nothing is hard-coded to a page.

Workflow

One feature at a time, behind review gates

Each feature gets a spec, its own Git branch, a measured comparison with Figma, and an archived record in blueprint/history/. You approve the spec, each review, and the final commit.

Set up once per site

  1. /onboard

    Checks the theme folder, Git, PHP, ACF Pro, and your Figma token. Sets the theme name, slug, and prefix.

  2. /figma <url>

    Reads colors, type, spacing, breakpoints, and sections. Proposes a build plan.

  3. /overview

    Turns the approved plan into a numbered feature list.

  4. /wp-theme

    Feature 1: theme skeleton, tokens, header, footer, and the page builder.

Build repeat per feature

  1. /feature

    Writes the spec for the next item, such as "Home page sections" or a post type.

  2. /implement

    Builds it in small reviewed steps using the /section, /acf, and /cpt recipes.

  3. /pixel-check

    Measures the local page against Figma at every breakpoint.

  4. /check optional

    Proves the spec's done-when criteria in the running site.

  5. /audit current optional

    Reviews escaping, sanitizing, nonces, queries, and performance.

  6. /complete

    Archives the spec, then asks before it commits and merges.

Then /feature again for the next item.

Pixel check

Measured against Figma, not eyeballed

/pixel-check renders the local page at each designed width, reads computed styles and boxes, and compares them with the Figma values. It reports the exact difference and the file to fix. It never edits code.

House rules

Plain WordPress your team can maintain

  • Classic PHP theme

    Template parts and get_template_part(). Any WordPress developer can read it.

  • Tokens from Figma

    Colors, type, and spacing live in assets/css/variables.css. Section CSS uses only those custom properties.

  • Safe by default

    Output is escaped, input is sanitized, forms use nonces, and queries are reviewed in /audit.

  • Fields in version control

    ACF field groups are saved as JSON in acf-json/ and committed with the code.

Setup

Start a project in five steps

  1. Create a site in LocalWP and activate ACF Pro.Turn on WP_DEBUG_LOG so the workflow can read PHP notices.
  2. Create an empty theme folder and copy the workflow files into it. 
    git clone https://github.com/saidMounaim/figma-wp-blueprint.git
cp -r figma-wp-blueprint/{AGENTS.md,CLAUDE.md,.claude,blueprint} \
  "wp-content/themes/your-theme/"
  3. Add your Figma token to .env in the theme folder.FIGMA_TOKEN=figd_... with the scope File content: Read-only. The file is git-ignored.
  4. Open the theme folder in Claude Code and run /onboard.Open the theme folder itself, not the site root.
  5. Run /figma with your design URL.Design, file, proto, and board links all work, with or without ?node-id=.
